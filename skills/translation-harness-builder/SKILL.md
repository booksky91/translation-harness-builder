# Translation Harness Builder

## 목표 및 산출물

프로젝트 안에 `translation-harness/`를 구축하고, 번역 담당자가 **진입점 → 작업별 정책 → 관련 상세 지식 → 출처·결정·검증 기록**을 찾고 사용할 수 있도록 문서를 연결한다. 작업 대상 프로젝트에 이미 운영 중인 하네스 경로가 있으면 해당 위치를 사용한다.

완성해야 할 산출물:
- 프로젝트 상황과 실제 파일을 안내하는 최상위 문서 및 작업별 문서 라우터
- 실행·문체·용어·검수 정책과 번역 단위 입출력 계약
- 필요한 프로젝트 고유 지식의 인덱스 및 상세 문서
- 출처, 번역 결정, 미확정 사항, 품질 검사, 변경 이력 기록 체계
- 번역 전에 필요한 하네스 본문을 읽게 하는 프로젝트 Rule

## 실행 절차

### 1. 프로젝트 상태 조사

1. 프로젝트 루트, 사용 중인 에이전트·편집기, 원문과 번역문, 언어·로캘, 매체, 문자열 식별자와 파일 포맷을 확인한다.
2. 현재 번역 가이드, 용어집, 캐릭터 설정, 스토리 자료, 기술 제약, 승인 기록, 프로젝트 Rule의 **실제 본문**을 조사한다.
3. `translation-harness/` 또는 이미 지정·운영 중인 하네스 경로의 파일·섹션·링크·기록 상태를 확인한다.
4. 기존 문서의 유효한 구조·작성된 사실·승인 기록을 유지한다. 필요한 폴더, 파일, 항목이 빠져 있으면 아래 명세에 따라 보강한다. 구조가 없는 영역은 직접 작성한다.
5. 확인되지 않은 소스 범위, 언어, 관계, 승인 주체, 검증 결과는 추측하지 않고 `UNKNOWN`이나 검토 대기 상태로 남긴다.

### 2. 계층 설계 및 파일 구성

[architecture.md](references/architecture.md)의 기본 트리와 생성 조건을 적용한다.

| 계층 | 기본 경로 | 책임 |
|---|---|---|
| 진입점 | `README.md` | 사용 목적, 범위, 문서 지도, 준비 상태, 최신 참조 경로 |
| 작업 라우터 | `TRANSLATION_GUIDE.md` | 작업 유형·입력 맥락별 필독 문서, 판단 우선순위, 보류 조건 |
| 작업 계약 | `PROMPT_TEMPLATE.md` | 번역 단위의 입력·출력, ID·태그 보존, 기록 방식 |
| 공통 정책 | `guides/` | 실행 순서, 목표 문체, 용어 판단, 대사·서사·기술 처리, QA |
| 프로젝트 지식 | `glossary/`, `characters/`, `story/`, `knowledge/`, `media/` | 원문에서 확인한 사실과 번역 판단을 조건별로 조회하는 인덱스·상세 |
| 운영 기록 | `operations/` | 출처, 결정, 이슈, 검증 결과, 변경 영향 |

- `README.md`, `TRANSLATION_GUIDE.md`, `PROMPT_TEMPLATE.md`, 실행·문체·용어·QA 기본 가이드, 용어집, 출처·결정·이슈·검증·변경 기록의 구조를 구성한다.
- 캐릭터·스토리·분기·도메인·UI·자막용 문서는 실제 프로젝트에 해당할 때 구성한다. 객체 수와 파일 수를 사전에 고정하지 않는다.
- 상위 문서는 **찾는 방법과 적용 범위**, 상세 문서는 **구체적 근거·조건·예외**를 소유하도록 분리한다. 같은 규칙을 여러 파일에서 독립적으로 확정하지 않는다.
- 문서 경로와 제목을 변경할 때는 기존 링크와 Rule 참조도 함께 갱신한다. 의미가 같은 기존 문서가 있으면 중복 파일을 만들지 않는다.

### 3. 문서별 정보 구조 작성

실제 파일의 제목·표·레코드를 [authoring-blueprints.md](references/authoring-blueprints.md), [domain-knowledge-blueprints.md](references/domain-knowledge-blueprints.md), [evidence-and-governance.md](references/evidence-and-governance.md)에 맞춰 작성한다.

각 문서에는 다음을 명확히 담는다.

- **문서 책임:** 해결할 번역 판단, 적용되는 작업, 상위 및 하위 문서
- **정보 식별:** 고유 ID, 원문 위치, 버전, 적용 범위(인물·상대·시점·루트·화면·기능 등)
- **내용:** 관찰 가능한 사실, 프로젝트 정책, 목표어 표현 후보, 사용 조건, 예외·반례
- **판정 상태:** 확인·추정·제안·승인·실제 매체 검증의 구분, 확인할 자료, 관련 이슈·결정 ID
- **이동 경로:** 상위 인덱스로 돌아가는 링크, 관련 상세 문서 및 원문 근거 링크

특히 다음 관계를 명확히 기록한다.

- **인물:** 화자→수신자 방향, 관계 단계, 호칭, 감정, 시점·루트 조건, 원문 대사 근거와 승인된 표현
- **서사:** 파일/장면/분기, 사건 순서와 확실성, 인물별 지식 상태, 정보 공개 시점, 번역상의 스포일러 위험
- **용어:** 원어·표기 변형·지칭 개념, 목표어 후보, 승인 상태, 적용 조건, 전역 치환 금지 사례
- **기술/매체:** 문자열 ID, 보존할 변수·태그·선택지·타임코드, 화면 맥락, 길이·형식 제약, 실제 검증 결과

문서 제목만 생성하고 완성으로 처리하지 않는다. 원본 근거가 없으면 **작성할 정보의 정의와 기록 양식**을 먼저 완성하고, 사실 레코드는 미조사 상태로 둔다.

### 4. 원문 근거 수집 및 상세 자산 작성

[population-and-maintenance.md](references/population-and-maintenance.md)를 따른다.

1. 파일·버전·단위 식별자를 `operations/SOURCES.md`에 등록한다.
2. 실제 원문·기존 번역·설정 자료에서 확인 가능한 사실을 해당 상세 문서에 기록한다.
3. `OBSERVED`, `CONTEXT_CONFIRMED`, `INFERRED`, `DRAFT`, `APPROVED`, `RUNTIME_VERIFIED`를 구분하고, 승인이나 실제 매체 시험을 수행하지 않은 상태를 임의로 확정하지 않는다.
4. 정책 변경이나 새로운 자료가 기존 용어·인물·스토리 규칙에 미치는 영향을 추적하고, 상위 인덱스와 관련 문서를 갱신한다.
5. 근거가 상충하면 `operations/ISSUES.md`에 출처와 적용 범위를 기록한다. 사용자 편집·승인 내역을 무단 삭제하지 않는다.

### 5. 프로젝트 Rule 연결

[rule-integration.md](references/rule-integration.md)를 읽고 사용 중인 Rule 형식에 맞춰 갱신한다. Rule이 없는 환경에서는 적용 가능한 기본 프로젝트 지침으로 `AGENTS.md`를 고려한다.

번역·현지화·교정·용어 결정·번역 QA를 시작하기 전에 다음을 수행하도록 Rule에 지시한다.

1. 실제 `README.md`와 `TRANSLATION_GUIDE.md` 본문을 읽는다.
2. 현재 번역 단위에 해당하는 공통 가이드와 분야별 인덱스를 찾는다.
3. 인물·스토리·용어·화면·기술 제약 중 필요한 **상세 문서의 본문과 해당 절**을 연다.
4. 출처와 승인 상태를 확인한다. 중요한 정보가 없거나 모순되면 확정을 보류하고 관련 이슈를 남긴다.
5. 적용한 문서 경로와 규칙·용어 ID를 작업 기록에 남긴다.

Rule의 다른 지침은 보존하고 관리 대상 구간만 추가·갱신한다. 파일을 기술적으로 자동 열람시키는 기능이 실제 환경에서 확인되지 않으면 검증되지 않았다고 보고한다.

### 6. 완성도 및 유지보수 검증

[quality-and-acceptance.md](references/quality-and-acceptance.md)의 기준으로 검사한다.

- **G0 구조·라우팅:** 필수 문서와 섹션, 상대 링크, 상위↔상세 경로, Rule의 실제 경로
- **G1 원문 근거:** 사실의 원본 ID·버전·위치, 적용 조건과 반례
- **G2 언어·승인:** 의미·문체·관계·용어 일관성, 승인 책임과 결정 기록
- **G3 실제 매체:** UI 표시, 태그·변수, 분기, 자막 등 구현 환경에서 확인된 결과

실시하지 않은 검증은 통과로 표시하지 않는다. 새 인물·용어·루트·원문 버전이 등장하면 상세 문서부터 수정하고 관련 인덱스, 가이드, 결정·QA·변경 기록의 영향을 확인한다.

## 결과 보고

활성 하네스 위치, 생성·수정한 문서와 핵심 내용, 실제 확인한 원본의 범위, 남아 있는 미확정/승인 대기 항목, 프로젝트 Rule 변경 위치, G0~G3 검증 상태를 보고한다. 근거 없는 사실을 채우거나 승인·검증 상태를 과장하지 않는다.

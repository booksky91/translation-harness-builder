# 최상위 문서와 공통 가이드의 **실제 생성 청사진**

각 문서의 필수 섹션·표·판정 규칙을 아래에 정의한다. 문서를 작성할 때 실제 프로젝트 파일을 만들고, 기존 문서에는 누락된 요소를 보완한다. `[...]`는 확인한 프로젝트 정보를 채울 자리다. 근거 없는 사실은 작성하지 않고 `UNKNOWN — 확인할 자료/질문`으로 기록한다.

## 1. 모든 문서의 공통 머리말

최상위 문서는 문서 목적과 적용 범위를 먼저 밝힌다. 내용마다 한 표준 상태 필드를 둔다. 긴 정보 덩어리에 메타정보를 반복 복사하지 않는다.

```md
# [문서의 역할을 설명하는 제목]

> 문서 역할: [이 문서가 해결하는 번역 문제 한 문장]
> 적용 범위: [언어쌍/매체/프로젝트 버전/세그먼트 또는 전체]
> 문서 상태: SKELETON | PARTIAL | EVIDENCE_READY | REVIEWED
> 기준 근거: [실제 소스 경로와 버전, 또는 UNKNOWN]
> 최종 갱신: [실제 수정 날짜 또는 미기록]
> 상세 참조: [상대 링크]
```

- `SKELETON`: 섹션과 판정 기준만 준비, 실제 프로젝트 근거 없음.
- `PARTIAL`: 일부 범위만 확인, 미조사 자료 존재.
- `EVIDENCE_READY`: 해당 범위의 실제 근거 위치와 해석을 작성했으나 승인 상태와 별도.
- `REVIEWED`: 문서 자체의 내용 검토 완료. **각 항목의 번역 승인·기술 검증을 의미하지 않는다.**
- 문서 상태와 항목 상태를 구별한다. `승인된 번역어`를 문서 전체가 `REVIEWED`라는 이유만으로 확대 해석하지 않는다.

## 2. `translation-harness/README.md` — **최상위 진입점**

**책임:** 하네스가 무엇을 관리하고 어떻게 진입하는지 알려준다. 상세 정책을 요약 반복하지 않는다.

실제 파일을 다음 구조로 작성한다.

```md
# Translation Harness — [프로젝트 식별명 또는 UNKNOWN]

## 1. 목적과 적용 범위
- 작업 목표 / 원문 언어 / 목표 언어·로캘 / 매체 / 대상 버전
- 근거가 있는 항목과 아직 미확정인 항목

## 2. 시작하기 — 반드시 읽을 문서
1. [번역 작업 중앙 가이드](TRANSLATION_GUIDE.md)
2. [단위 작업 입출력 계약](PROMPT_TEMPLATE.md)
3. 중앙 가이드에서 현재 작업 유형에 연결하는 상세 규칙 본문

## 3. 하네스 계층과 단일 기준 위치
| 계층 | 관리 대상 | 시작 문서 | 조건부 상세 조회 |

## 4. 빠른 작업별 탐색
| 하려는 작업 | 먼저 열 문서 | 다음 확인해야 할 정보 |

## 5. 소스·판정·승인 상태
- 출처 목록: [operations/SOURCES.md](operations/SOURCES.md)
- 미해결: [operations/ISSUES.md](operations/ISSUES.md)
- 결정 기록: [operations/DECISIONS.md](operations/DECISIONS.md)
- 문서 생성 완료와 번역·실행 검증 완료의 차이

## 6. 변경·검수·문서 사용법
- 번역 전 문서 읽기 / 문서 갱신 시 근거 기록 / Rule 경로
- 문서가 누락되거나 접근 불가할 때의 처리

## 7. 현재 미확정 사항
| 항목 | 알 수 없는 이유 | 검증에 필요한 자료/담당 |
```

**실제 작성 기준:** 모든 링크가 존재해야 한다. 조건부 상세 문서가 없으면 없는 이유를 `해당 없음` 또는 `아직 데이터 없음`으로 구분한다. README에 캐릭터 말투나 루트 결말 전문을 중복 기재하지 않는다.

## 3. `TRANSLATION_GUIDE.md` — **중앙 라우터/판정 우선순위**

이 문서는 번역 업무의 *내비게이션 메뉴*다. 여기만 읽고 번역하는 것을 금지한다. 상세 본문을 읽을 때 발생하는 비용을 줄이되, 판단하는 데 필요한 자료를 생략해서는 안 된다.

```md
# Translation Guide — 문서 로드와 판정 라우팅

## 0. 이 문서의 한계
- 본 문서는 목차와 로드 규칙이다. 상세 가이드/원문을 대신하지 않는다.

## 1. 모든 작업의 공통 필독 경로
- README → 실행 가이드 → 품질·승인 정책 → 필요 상세 자료

## 2. 작업 유형별 상세 문서 로드 표
| 작업 상황/검출 조건 | 반드시 읽을 공통 가이드 | 필요한 인덱스 | 반드시 열 상세 문서 | 실패 시 처리 |

## 3. 판단 우선순위와 충돌 처리
- 변형 불가 원문/기술 구조 → 현재 장면·화면 맥락 → 승인 표기 →
  조건부 화자/스토리/제품 규칙 → 공통 문체 → 단순 시범 표현

## 4. 중단/보류 조건
- 화자/관계/시점이 달라 의미가 바뀌는 경우 등
- 독음·고유 표기가 미확정이고 결정에 필수인 경우
- 보호 태그/분기/시간코드/문자열 길이 등 실장 위험

## 5. 입력과 출력의 최소 계약
- 단위 ID, 원문, 장면/화면 맥락, 읽은 문서, 번역 후보, QA·미해결 기록

## 6. 사용 중 문서 버전 확인과 변경 원칙
- 현재 기준·승인 상태·링크 대상 갱신
```

**로드 표의 필수 행:** 모든 번역/교정, 용어/고유명사, 대사/화자(있을 때), 서술·분기(있을 때), UI/기술·자막(있을 때), 불확실·충돌·승인, 신규 정책 제정. 이 표는 *실제로 생성된 파일의 상대 링크*로 작성한다. 없는 문서 링크를 임의 생성하지 않는다. 어떤 문서를 읽어야 할지 전혀 알 수 없다면 `UNKNOWN`인 것을 밝히고 보류한다.

**충돌 예시 작성 규칙:** 승인된 일반 용어와 특정 장면의 의도적 말장난이 충돌하는 경우, 전역 치환 대신 해당 장면의 원문 ID를 남겨 예외·승인 대상으로 올리게 한다. 시나리오 후반 정보가 초반 발화에 역유입되면 현재 장면을 우선한다.

## 4. `PROMPT_TEMPLATE.md` — **번역 에이전트의 단위 작업 계약**

이 문서는 에이전트에 전달할 **반복 가능한 입력 슬롯·필수 처리 순서·산출물**이다. 원본 파일 포맷이 제공되지 않았으면 `unit_id` 같은 의미 슬롯만 정의하고 실제 필드 매핑은 나중에 적는다.

```md
# 번역 단위 작업 계약

## 1. 역할과 목적
- 목표 언어, 보존할 의미·톤·기술 요소, 허용/금지되는 의역

## 2. 작업 시작 전 실제 로드 확인
- 읽은 최상위 문서/세부 문서 경로·대상 절·버전
- 못 읽은 문서의 목록과 중단 또는 대안 요청 조건

## 3. 입력 의미 필드
| 이름 | 필수? | 의미 | 누락 시 처리 |
| unit_id | 필수 | 원문 단위의 유일한 식별자 | 식별 불가 보고 |
| source_location | 권장 | 출처/파일/행/페이지/타임코드 | 위치 누락 보고 |
| original_text | 필수 | 변경 전 원문 | 번역 중단 |
| unit_type | 조건부 | 대사/지문/버튼/선택지/자막 등 | 추정 금지 |
| context_before_after | 필요 시 | 인접·장면/화면 문맥 | 추가 탐색 |
| speaker_addressee | 대사 시 | 화자, 수신자와 확신도 | 조건부 규칙 보류 |
| route_state | 서사 시 | 시점, 루트, 공개 사실 | 스포일러 방지 |
| protected_elements | 기술 시 | 변수·태그·연결·시간코드 | 변경 금지 |

## 4. 작업 순서
- 현재 단위 식별→원문·맥락 확인→하네스 상세 조회→번역 초안→QA→기록

## 5. 출력 계약
| 필드 | 내용 |
| unit_id | 입력과 동일 |
| target_draft | 번역 후보 문장 |
| applied_refs | 실제 읽은 상세 문서/앵커, 적용한 용어 ID |
| context_decision | 화자/수신자/서술 시점/제한 조건 판정 |
| uncertainties | 미확정 사항, 충돌, TECH_REVIEW 필요 여부 |
| review_state | DRAFT/CONTEXT_REVIEW/LANGUAGE_REVIEW/TECH_REVIEW 등 |

## 6. 단위 경계와 기술 요소 보호
- 원본 ID, 링크, 태그, 명령, 변수, 타이밍, 원문 객체 임의 변형 금지

## 7. 다건 작업·경계 전환
- 항목 순서/ID 대응 유지, 새로운 화자/루트/화면 등장 시 세부 문서 다시 읽기
```

**실제 내용 조건:** 실제 스키마가 `CSV`면 열을, `.po`면 메시지 컨텍스트/ID를, 자막이면 타임코드를 해당 프로젝트 기준으로 정의한다. 가상의 `technical.source_markup` 같은 필드를 무조건 요구하지 않는다. 번역문 제안과 승인된 최종 출력의 위치를 분리한다.

## 5. `guides/01_EXECUTION.md` — **공통 번역 실행 정책**

```md
# 01 — Translation Execution

## A. 작업 단위의 정의와 필드 매핑
- 원본 단위, 식별자, 변경 가능 필드, 참조할 문맥, 단위 합치기/분할 규칙

## B. 번역 1단위 순서
1. 고정 ID/원문/종류/메타데이터 읽기
2. 필요한 범위까지 전후 맥락 확인
3. 작업 유형에 해당하는 정책 및 상세 지식 문서 읽기
4. 원문 의미·불확실성·관계·조건 정리
5. 번역 후보 만들기
6. 의미·문체·용어·기술 검수
7. 미해결/승인/실장 상태 및 참조 경로 기록

## C. 판단 우선순위
| 우선순위 | 판단 근거 | 예외/충돌 시 행동 |

## D. 근거·번역·검증 상태 구분
| 상태 | 의미 | 이 상태로 허용되는 작업 |

## E. 산출 기록의 기본 항목
- unit_id, original_source, work_context, applied_refs,
  target_draft, alternatives, meaning_check, technical_check, review_state

## F. 작업 중 금지되는 자동 보정
- 원문 추정 사실을 확정하기, 인물/경로 오인, ID 변경, 원문 태그 생성·삭제 등
```

**상세 관리:** `context_before_after`는 기계적으로 일정한 5줄에 고정하지 않는다. 화자·수신자·분기 의미를 이해할 수 있을 때까지 맥락을 확장한다. 충돌 시 일반 문체보다 현재 단위의 의미와 실제 보호 조건을 우선한다. 작업자는 매 단위 `읽은 실제 문서`를 기록한다.

## 6. `guides/02_DIALOGUE_VOICE.md` — **대사와 화법의 판단 방법** (조건부)

```md
# 02 — Dialogue, Voice and Address

## A. 발화 환경 식별 절차
- 누가 말하는가 / 누구에게 / 어느 시점과 장소에서 / 목적·감정 / 직접 인용 여부

## B. 원문 언어 형태와 목표 언어 말투 구분
| 원문 관찰 | 불필요한 일반화 | 목표 언어에서 검토할 요소 |

## C. 기본 보이스·조건부 보이스의 우선순위
- 화자 기본 보이스와 '화자→수신자→관계 단계→장면 예외' 구별

## D. 호칭·애칭·직책·집단/익명 발화
- 표면 호칭 보존, 지칭 대상 확인, 친족/친밀 관계 추정 금지

## E. 관계 변화·연기·농담·위협·고백의 예외
- 일시적 말투 변동을 일반 규칙으로 승격하는 조건

## F. 상세 지식 탐색
- CHARACTER_BIBLE 인덱스 → 화자 상세 → 해당 상대/시점 절

## G. 화법 QA
- 같은 관계 단계에서의 호칭/종결 일관성, 의도적 이탈의 근거
```

**세부 항목:** 말투는 문장 끝만이 아니라 인칭 선택, 높임법, 호칭 사용, 말버릇, 어휘 강도, 말줄임, 리듬, 독백 여부까지 분리해 관리한다. 같은 `선배` 호칭이 상황에 따라 실제 직책인지 장난인지 구분한다. 상대가 확인되지 않으면 상대별 규칙을 적용하지 않는다. 관련 캐릭터 문서가 없으면 생성·확인 중임을 기록한다.

## 7. `guides/03_NARRATION_STORY.md` — **서사·시점의 판단 방법** (조건부)

```md
# 03 — Narration, Story and Information Disclosure

## A. 서술자/관찰자/인용 화자 구별
- 무명 화자=특정 인물이라고 단정하지 않는 규칙

## B. 진술의 확실성 보존
- 관찰/소문/전언/추측/거짓말/기억/미확인/서사적 진실 구별

## C. 시간·루트·분기 격리
- 장면·루트·과거/현재·분기 조건별로 적용 가능한 지식 경계

## D. 정보 공개 시점과 스포일러 보호
- 각 화자/플레이어/독자가 어느 시점에 무엇을 아는가

## E. 독백/지문/회상/선택지의 표현 원칙
- 시점 고정, 대명사 복원 금지, 의도적 침묵/불확실성 보존

## F. 민감한 맥락의 사실적 재현
- 피해자/가해자 관점과 동의·강압 혼동 금지, 원문 강도 보존

## G. STORY_BIBLE 및 타임라인 참조 절차
- 현재 파일/장면→해당 상세 루트→지식 공개 표→현재 원문
```

**주의:** 루트 인덱스의 파일 정렬 순서를 실제 시간 순서로 선언하지 말 것. 나중에 밝혀지는 정체·혈연·연인 관계를 앞 장면으로 소급 적용하지 말 것. 작품의 공식 시간선이 없으면 장면 단서만 모으고 순서 미확정으로 남긴다.

## 11. `guides/07_QA_APPROVAL.md` — **문장 승인·기술 승인·이슈 관리**

```md
# 07 — Quality Assurance and Approval
```

## 12. `guides/08_CASEBOOK.md` — **판단 가능한 실제 사례집** (조건부)

사례가 없는 새 프로젝트에서 빈 가상 성공 사례 10개를 복제하지 않는다. 실제 원문/검수 오류가 생기면 생성하거나 추가한다.

```md
# 08 — Translation Casebook

## 사용 범위와 주의
- 사례는 조건을 확인하는 교육·검수 보조이며 승인된 전역 정책과 다름

## 사례 인덱스

- 원문 출처 ID/버전:
- 장면·화면·화자/상대·루트 조건:
```

## 13. 정책 문서와 상세 지식 문서의 관계

- `02_DIALOGUE_VOICE.md`는 **말투를 어떻게 정하는지**, 인물 상세 파일은 **이 인물이 해당 상대에게 실제로 어떤 말투를 쓰는지**를 담는다.
- `03_NARRATION_STORY.md`는 **스포일러를 어떻게 막는지**, 스토리 상세 파일은 **이 장면의 어떤 정보가 누구에게 공개됐는지**를 담는다.
- `05_TERMS_AND_NAMES.md`는 **용어 표기 결정 절차**, `GLOSSARY.md`는 **현재 결정된 실제 대응 항목**을 담는다.
- `07_QA_APPROVAL.md`는 **승인의 기준**, `operations/DECISIONS.md`는 **누가 어떤 결정을 승인했는지**를 담는다.
- `01_EXECUTION.md`는 **반복 작업 순서**, `PROMPT_TEMPLATE.md`는 **모델 입력/출력 규약**, `TRANSLATION_GUIDE.md`는 **필요 자료 조회 순서**를 각각 담당한다.

이 분리가 깨지면 상위 문서를 요약만 읽고 상세 사실을 놓치기 쉽다. 각 문서의 역할을 겹치게 쓰지 말고 링크로 연결하라.

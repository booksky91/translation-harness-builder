# 원문 의미 분석과 번역 하네스 실내용 집필 방법

원본이 있는 프로젝트에서 최종 산출물은 빈 서식, 문자열 표본, 단순 조사표가 아니다. **번역 작업에 곧바로 참조할 수 있는 프로젝트 고유 판단 지식**을 실제 문서에 집필한다. 어떤 장르·언어·매체든 해당 프로젝트의 소스가 허용하는 정보만 다루고, 조건·예외·근거를 표시한다.

## 목차
1. 탐색 결과에서 번역 지식으로 전환
2. 이중 분석: 국소 문맥과 전체 코퍼스 비교
3. 대상 자산별 실내용 작성법
4. 단일 지식 항목의 내용 밀도
5. 문서 간 반영·라우팅
6. 심층 재검토와 반례 검사
7. 산출물의 실질적 사용성 검사

## 1. 탐색 결과에서 번역 지식으로 전환

원문을 읽는 순서를 [corpus-ingestion.md](corpus-ingestion.md)에서 확인한다. 추출된 문자열·화자 ID·장면·기능 명칭은 **재료**이고, 하네스에 필요한 것은 그 재료로 확인한 **번역 시의 판단 규칙**이다.

각 유의미한 관찰에 다음 질문을 순서대로 적용한다.

1. **관찰:** 원본의 어느 위치에서 누가/무엇이/어떤 조건으로 발화·표시·설명되는가?
2. **문맥:** 앞뒤 사건, 수신자, 역할, 상태, 시점, 기능과 연결하면 무엇이 달라지는가?
3. **반복:** 같은 대상이 다른 파일·장면·화자·화면에 등장할 때 일관성과 차이는 무엇인가?
4. **해석:** 직접 확인된 정보와 정황상 가능한 해석을 구별할 수 있는가?
5. **번역 영향:** 목표 언어 선택(호칭, 높임법, 용어, 문장 길이, 어조, 의미 공개, 태그 처리)은 무엇이 달라져야 하는가?
6. **적용 조건:** 이 판단이 성립하는 대상·상대·시점·루트·기능·버전은 어디까지인가?
7. **반례와 예외:** 다른 문맥에서는 오히려 사용하면 안 되는 표현이나 판단이 있는가?
8. **근거와 상태:** 최소한의 원문 근거, 단위 ID, 판단 상태, 검토할 자료를 연결했는가?

추출 결과가 여러 자산을 갱신해야 하면 각각을 업데이트한다. 예: 한 장면에서 인물 간 관계가 바뀐다면 **장면 카드의 사건·정보 공개**, **양쪽 인물의 방향별 화법**, **관련 호칭 용어**, **중앙 라우터**의 적용 경로를 교차 점검한다. 단, 같은 원문 사실을 여러 문서에서 독립적으로 확정하지 않는다.

## 2. 이중 분석: 국소 문맥과 전체 코퍼스 비교

### 1차: 장면·파일 단위

- 진행 중인 사건/업무와 현재 상태를 한두 단락으로 요약한다. 이 요약은 번역 결정에 직접 필요한 인과관계 중심이며, 확인되지 않은 비밀을 사실로 기록하지 않는다.
- 등장 인물·화자·수신자·서술자를 구분하고 호칭·사회적 관계·관점·감정을 원문 맥락에 연결한다.
- 원문에서 강조·농담·완곡·위협·경고·부정·모호성이 어떤 역할을 하는지 조사한다.
- 이전/이후와 비교해야 할 변화, 재등장 용어, 상태/분기 제약을 후보로 남긴다.

### 2차: 동일 대상의 전 범위 비교

- **인물:** 해당 화자의 여러 장면을 묶어 화법의 안정된 특성과 상대·시점·감정별 변화를 분류한다. 한 문장의 말끝만으로 전역 말투를 정하지 않는다.
- **관계:** 같은 두 인물이 말할 때도 `A→B`와 `B→A`를 따로 조사한다. 관계의 변화·역할·공개/비공개 상황을 비교한다.
- **서사:** 사건의 앞뒤 근거, 공통 루트와 분기 결과, 서술자 신뢰성, 각 인물이 그 시점에 알고 있는 정보의 범위를 대조한다.
- **용어/명칭:** 동일 표면형의 여러 지칭 대상과 같은 개념의 여러 표기를 비교한다. 문맥마다 의미가 다른 경우 하나의 전역 번역어로 합치지 않는다.
- **UI/전문 분야:** 같은 텍스트의 화면별 동작, 다른 상태의 안내문, 제품 버전, 경고·오류의 실제 효과를 비교한다.

2차 비교에서 검증된 일반 규칙만 상위 정책으로 승격한다. 일부 사례에만 해당하는 판단은 조건부 상세 규칙으로 남긴다. 개별 번역 문장 1~2개를 작성했다고 해당 분야의 조사·집필이 끝났다고 보지 않는다.

## 3. 대상 자산별 실내용 작성법

### A. `guides/` — 일반론을 프로젝트에 작동하는 정책으로 바꾸기

- 실행 가이드에는 **실제 소스 형식의 ID 위치, 번역 가능한 필드, 원문/번역문 보존 조건**과 흐름을 적는다. 아직 확인하지 않은 엔진/서식 기능을 사실처럼 적지 않는다.
- 목표 문체 가이드에는 프로젝트의 독자·로캘·장르·매체를 근거로 문장별 권장 표현, 표현 강도, 예외, 근거를 기록한다. 비슷한 장르의 관습을 그대로 프로젝트 정책으로 전용하지 않는다.
- 대사·서사 가이드에는 전체 코퍼스에서 확인한 공통 경향과 **상세 인물·장면 카드로 이동하는 규칙**을 담는다.
- 용어 가이드에는 실제 등장한 고유명사/개념의 독음·의미 충돌·명칭 표기 규칙을 담고 `GLOSSARY.md`를 기준으로 연결한다.
- 기술·QA 가이드에는 해당 프로젝트가 실제 사용하는 형식, 변수, 선택지, 화면·자막·구현 제약과 검사 절차를 적는다.
- `08_CASEBOOK.md`에는 원문에서 실제 확인한 **선택 이유가 있는 번역 사례**를 축적한다. 단순 원문·번역문 두 열만 채우지 않는다.

### B. `characters/` — 인물·방향별 관계·시점별 말투

1. 실제 원문에 등장하는 화자/인물의 별칭·원문 표기·역할·등장 파일을 수집하고 동일 인물 여부를 출처로 확인한다. 시스템 메시지나 익명 화자를 무단으로 특정 인물에 합치지 않는다.
2. 인물별 프로필을 생성해 **성격·역할의 관찰과 추론을 분리**하고, 해당 인물의 발화 다수를 비교한 어휘·말투·리듬·대인 태도를 작성한다.
3. 수신자별로 독립된 `화자 → 수신자 → 관계 단계/시점` 절을 만든다. 호칭, 높임·낮춤, 거리감, 문장 길이, 표현 금기, 실증 대사 ID, 예외를 적는다.
4. 관계가 달라지는 사건/장면이 있다면 변화의 **시작 조건과 적용 종료 조건**을 명시하고 스토리 카드의 해당 절로 연결한다.
5. 원문의 언어 특징과 목표어 화법 제안을 분리한다. 목표어 존대법처럼 언어쌍에 민감한 규칙은 실제 작업의 로캘을 확인하고 작성한다.
6. `CHARACTER_BIBLE.md`에는 확인된 인물 전체의 탐색표, 별칭, 상대별 프로필 절의 연결 경로, 아직 미확정인 관계를 갱신한다.

**깊이 검사:** 등장 인물이 여럿인데 대표 화자 몇 명만 작성했다면 그 범위만 완료한 것이다. 인물이 말하는 상대가 여러 명인데 한 가지 전역 말투만 작성했다면 해당 인물의 관계 분석은 미완료다. 원본에 수신자 단서가 없으면 명시적으로 `수신자 미확정`으로 처리한다.

### C. `story/` — 사건·인물 지식·정보 공개·분기

1. 확인된 파일/장면/절의 **실제 의미**를 요약한다. 표면적 키워드나 파일 순서만 나열하지 않는다.
2. 사건의 동기, 발생 조건, 인과관계, 변경된 상태, 대사/선택지에 미치는 영향을 원문 근거와 함께 작성한다.
3. 관찰된 선후 관계와 추정된 순서를 구분한다. 선택·분기가 있으면 **공유 구간 / 조건부 구간 / 상충 가능한 결과**를 분리한다.
4. 시점마다 **인물별로 이미 알고 있는 정보와 아직 알 수 없는 정보**를 기록해 번역에서 후일의 사실을 미리 드러내지 않도록 한다.
5. 한 장면이 다른 장면·인물 프로필·용어의 번역 판단을 변경하면 적용 조건과 링크를 추가한다.
6. `STORY_BIBLE.md`는 장면·분기 인덱스를, `FILE_INDEX.md`는 물리 파일↔장면 매핑을, `TIMELINE_AND_REVEALS.md`는 시간·지식 공개 제약을 관리한다. 사건군 상세에는 장면의 실제 내용과 번역 위험을 적는다.

**깊이 검사:** 원본에 서사/분기가 있는데 파일 색인과 선택지 목록만 존재하면 스토리 하네스는 미완료다. 접근 가능한 장면에 대한 맥락 요약, 변화, 정보 공개, 번역 영향이 있어야 한다.

### D. `glossary/`와 `knowledge/` — 지칭 개념과 용어 적용 조건

1. 원문에서 실제로 반복되거나 번역 선택에 영향을 주는 이름·용어·개념을 식별한다. 출현 횟수가 적더라도 기능·서사상 중요한 항목은 포함한다.
2. 표면형·변형·독음·지칭 대상·원본 위치를 구분해 등록한다. 다른 이름이 같은 대상인지, 같은 이름이 다른 대상을 가리키는지 확인한다.
3. 목표어 후보와 선택 근거를 작성한다. 승인된 번역어가 없다면 **사용 가능한 제안 초안**을 구체적으로 작성하되 승인으로 둔갑시키지 않는다.
4. 적용 조건(화자/관계/시점/루트/기능/버전)과 예외를 기록한다. 전역 치환하면 안 되는 경우를 명시한다.
5. 개념 간 선행·포함·대립·상태 전이 등 번역에 영향을 주는 구조는 `DOMAIN_BIBLE`과 필요한 `topics/`에 서술하고 용어 ID를 연결한다.

**깊이 검사:** 원문 표현과 번역 후보만 나열하고 실제 지칭 대상·적용 조건·반례가 비어 있으면 용어 판단 지식으로 보지 않는다.

### E. `media/` 및 `guides/06_FORMAT_AND_TECH.md` — 구현 문맥

- 화면/기능별 문구의 사용 위치, 실행 상태, 버튼/오류/알림 역할, 사용자에게 유도하는 행동을 확인한다.
- 숫자·변수·태그·플레이스홀더·엔진 제어 구문·선택지 ID·타임코드가 실제로 어떤 의미인지 확인하고 보존 규칙을 적용한다.
- UI/자막의 글자 수·줄바꿈·표시 제약은 실제 자료·빌드·명세에서 확인한다. 테스트하지 않은 제약을 단정하지 않는다.
- 같은 표면 문자열이라도 화면·상태마다 다른 번역이 필요하면 별도 적용 조건을 둔다.

### F. `operations/` — 기록이 아니라 후속 판단이 가능한 근거 관리

- `SOURCES`: 파일 및 실제 열람·의미 반영 범위, 원문 ID 체계와 증거 위치.
- `DECISIONS`: 확정된 정책과 미승인 번역 제안을 구별하고 결정 이유·효력 범위를 기록.
- `ISSUES`: 접근 실패, 모순, 미확인 관계, 번역 선택에 영향을 주는 질문·우선순위.
- `QA_LOG`: 내용 검토, 반례 검사, 기술·실행 시험을 별도 결과로 기록.
- `CHANGELOG`: 특정 원본·규칙 변화가 어떤 관련 문서와 기존 번역에 영향을 주는지 기록.

## 4. 단일 지식 항목의 내용 밀도

실제 문서의 중요한 항목은 다음 형태로 작성한다. 필드명은 프로젝트 서식에 맞게 조정해도 의미는 빠뜨리지 않는다.

```md
### [지식 ID] — [실제 원문에서 확인한 주제]
- 출처: [scope_id/source_id/unit_id와 실제 위치 또는 링크]
- 직접 관찰: [원문이 실제로 나타내는 내용; 짧은 관련 근거]
- 앞뒤 맥락: [장면·수신자·기능·조건]
- 반복/대조: [다른 장면·표현·상태와 비교한 사실 또는 '미확인']
- 번역 판단: [목표어에서 선택할 표현·어조·용어·보존 방식]
- 적용 범위: [누가/언제/어디서/어떤 조건으로]
- 비적용/반례: [이 판단이 틀리는 조건]
- 상태: [관찰/해석/번역 제안/승인/실장 검증을 구분]
- 관련 자료: [필요한 인덱스·상세·결정·이슈 링크]
```

- 문서를 작성할 때 해당 필드가 본문에 **구체적 정보**로 채워졌는지 확인한다. `[작성 예정]`만 남은 상세 카드를 완료로 처리하지 않는다.
- 실무적으로 중요한 규칙에는 짧고 정확한 **원문 사례와 목표어 후보 또는 판단 방향**, 왜 그렇게 처리했는지, 언제 예외인지 적는다.
- 표현을 실제로 제안할 수 있는 상황에서 모든 목표어 값을 `UNKNOWN`으로 방치하지 않는다. `DRAFT` 후보와 확정되지 않은 사실을 구별해 작업 가능한 초안을 작성한다.
- 아직 번역할 목표어를 모른다면 목표어 정책·후보를 창작하지 않되, 출처 기반의 의미·문맥·제약 분석은 채운다.
- 긴 원문 전체나 타인의 저작물을 무단으로 복제하는 문서가 되지 않도록, 필요한 짧은 근거와 안정적인 원문 위치/ID 위주로 연결한다.

## 5. 문서 간 반영·라우팅

1. 실제 발견한 인물·개념·장면·기능의 **개수와 이름**을 소스와 대조해 인덱스를 작성한다. 임의의 인물 수·루트 수를 목표로 잡지 않는다.
2. 각 상세 문서는 상위 인덱스, 원문 근거, 영향받는 다른 분야의 문서, 상태·결정을 연결한다.
3. `TRANSLATION_GUIDE.md`에 번역자가 **어떤 원본 조건에서 어떤 상세 파일의 어떤 절을 읽을지** 실제 경로로 연결한다.
4. 상위 `README.md`는 프로젝트의 진행 상태와 하네스 영역, 필독 경로를 설명하되 상세의 전문을 중복하지 않는다.
5. 이미 존재하는 승인된 정책을 침해하지 않으며, 새 관찰과 충돌하면 검토 이슈·영향 범위를 명시한다.

## 6. 심층 재검토와 반례 검사

- 같은 용어·인물·개념이 처음 등장한 장면과 후반/다른 분기에서 사용된 장면을 비교해 누락된 예외를 찾는다.
- 다른 화자의 발화를 섞지 않았는지, 화자→수신자 방향이 뒤집히지 않았는지, 소문·거짓·회상·미래 정보를 객관적 사실로 승격하지 않았는지 검사한다.
- UI·선택지·자막의 실제 기능·조건과 작성한 번역 지침이 맞는지, 태그·변수를 임의로 수정하도록 유도하지 않는지 검사한다.
- 각 범주에서 대표 기록을 무작위 또는 위험도 기준으로 원문에 다시 대조한다. 오역·잘못된 범위·빈 정보가 발견되면 **같은 추출 방법으로 작성한 나머지 항목도 재검토**한다.
- 등장했던 인물/장면/용어/기능의 목록을 상세 문서 인덱스와 역으로 대조해 빠진 대상을 식별한다.

## 7. 산출물의 실질적 사용성 검사

최종 문서가 주제별 소제목과 표만 있는 경우 미완료다. 다음 질문에 실제 파일 링크와 근거를 제시해 답할 수 있어야 한다.

- 특정 발화·문구의 번역을 시작할 때 누구의 어떤 말투·용어·기술·서사 규칙을 읽어야 하는가?
- 그 규칙은 어떤 원문에서 도출했고 **어느 조건까지 적용하는가?**
- 비슷한 장면인데 다른 표현을 써야 하는 반례는 무엇인가?
- 미확정이 있다면 원문을 아직 읽지 않은 것인가, 읽었지만 확인 불가능한 것인가?
- 새 원문이 추가되면 어떤 지식 카드와 번역 단위가 영향을 받는가?

답할 수 없다면 링크 수·원문 행 수와 무관하게 해당 영역의 집필을 계속한다. 범위·완료·검수 판정은 [coverage-and-resumption.md](coverage-and-resumption.md)에 따른다.

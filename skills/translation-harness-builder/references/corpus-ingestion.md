# 원본 코퍼스 발견·전수 열람·분기 해석 프로토콜

실제 원본이 존재하면 문서 양식보다 **원본의 조사 범위와 맥락 이해**를 우선한다. 파일 목록 추출, ID 부여, 행 수 계산은 조사 준비일 뿐, 원문 읽기나 의미 분석 완료의 증거가 아니다. 프로젝트의 모든 번역 대상 자료와 문맥을 제공하는 자료에 적용한다.

## 목차
1. 범위 확정과 원본 인벤토리
2. 자료 형식별 안전한 읽기
3. 번역 단위 및 실행 문맥 복원
4. 파일·장면·문맥을 실제로 읽는 절차
5. 대량 자료 배치 처리
6. 누락·접근 실패·변경 관리
7. 원본 조사 수락 기준

## 1. 범위 확정과 원본 인벤토리

1. 작업 대상의 프로젝트 식별자와 소스 경계를 명시한다. 같은 작업 공간에 복수 작품·제품·로캘이 있으면 **대상별 소스 목록과 출력 하네스 경로**를 따로 정한다. 공통 파일인지 소속 불명인지 출처를 먼저 판정한다.
2. 소스 폴더를 재귀적으로 열람한다. 프로젝트 설정, 추출·빌드 파이프라인, 매핑 파일, 기존 번역, 용어집, 장면·상태 정의, 테스트 자료를 함께 조사한다. 원문 이외에 문맥을 결정하는 자료도 조사 대상이다.
3. 확장자나 폴더명만으로 무관하다고 제외하지 않는다. 문자열을 동적으로 구성하는 코드, 조건문, 대사 화자 변경 명령, UI 컨텍스트 파일처럼 번역 결과에 영향을 주는 파일을 포함한다.
4. 동일 원본의 복사본·버전·추출본은 서로 다른 일차 자료로 중복 계산하지 않는다. 파일 해시·버전·경로·생성일·참조 관계로 우선 소스를 결정하고 보조 자료를 연결한다.
5. 원본 접근 범위를 `operations/SOURCES.md`에 기록한다. 기존 형식을 유지하되 다음 정보를 추가한다. 다중 프로젝트라면 각각의 하네스에서 자신의 소스만 기록한다.

| 필드 | 기록 내용 |
|---|---|
| `scope_id` | 해당 자료를 소유한 프로젝트·제품·작품 식별자 |
| `source_id` | 원본 파일에 대한 안정 ID; 경로 변경 시에도 연결 유지 |
| `path / version / hash` | 상대 경로, 자료 버전 및 확인 가능한 지문 |
| `format / encoding` | 텍스트·JSON·CSV·스크립트·자막·문서·이미지 등 및 인코딩 |
| `source_role` | 번역 대상 원문 / 맥락 근거 / 기존 번역 / 기술 설정 / 참고 자료 |
| `units` | 실제 식별된 문자열·장면·절·cue·행 등과 고유 키 구성법 |
| `reading_state` | `DISCOVERED`, `OPENED`, `CONTEXT_READ`, `EXTRACTED`, `INTEGRATED`, `VERIFIED`, `BLOCKED`, `OUT_OF_SCOPE` 중 관찰된 상태 |
| `evidence` | 실제 열람 위치, 분석 근거의 단위 ID, 처리 기록 |
| `reason / next_action` | 제외·차단·대기 사유 및 재개 조건 |

`DISCOVERED`는 이름을 발견했다는 뜻이다. 파일을 통계·정규표현식으로 검색했다고 `CONTEXT_READ`로 올리지 않는다. `INTEGRATED`는 유의미한 번역 지식이 관련 하네스 문서에 실제 반영되고 출처가 연결된 상태다. 정보가 없는 파일이라면 그 이유와 확인 근거를 남긴다.

## 2. 자료 형식별 안전한 읽기

- **텍스트·마크다운·스크립트:** 인코딩을 확인하고 원본 구조를 유지해 읽는다. 실행 가능한 소스에서 문자열 리터럴, 주석, 상태 제어, 분기·콜백을 구분한다. 미확인 코드 실행은 하지 않는다.
- **CSV/TSV/XLSX/테이블:** 열 이름, 헤더, 시트, 셀 타입, 키, 순서, 메타 필드, 중복 키를 확인한다. 한 행이 장면 문맥을 완전히 표현한다고 가정하지 않는다.
- **JSON/YAML/XML:** 트리 경로, 배열 순서, 조건 노드, 연결 ID와 텍스트 필드를 구분한다. 번역 대상 필드와 로직을 보존한다.
- **엔진·이벤트·대사 스크립트:** 화자 상태 변경, 이름창, 분기 명령, 공통 이벤트 호출, 점프·복귀, 조건 플래그, 변수 치환을 추적한다. 대사 텍스트만 골라내고 상태 흐름을 버리지 않는다.
- **영상/자막/오디오:** cue와 타임코드, 화면·발화자·동시 발화·효과음, 필요한 경우 구간별 시청 가능 여부를 확인한다.
- **UI·문서·이미지:** 화면 위치·사용자 상태·동작 결과·참조 이미지, 도표·캡션·표 머리글 등 원문 의미에 필요한 문맥을 연결한다. 읽을 수 없는 매체는 텍스트만 보고 맥락을 확정하지 않는다.
- **압축 파일:** 내용물을 안전하게 열람할 수 있을 때 안쪽 자료를 분류한다. 압축 파일이 작업 입력으로 반드시 있어야 한다는 전제를 두지 않는다.

읽기 도구가 형식을 지원하지 않으면 가능한 추출·변환을 검토한다. 원본을 덮어쓰거나 임의 실행하지 말고, 추출된 텍스트가 원본과 어떻게 연결되는지 기록한다. 도구로 파악할 수 없는 속성은 `BLOCKED`와 필요한 확인 절차로 남긴다.

## 3. 번역 단위 및 실행 문맥 복원

각 소스는 번역 단위를 식별하되, 단위에 의미를 부여하는 주변 맥락도 연결한다.

- **단위 ID:** 원본 고유 키를 최우선한다. 없으면 `scope/source/path/position` 등 안정한 조합을 정의하고 충돌·버전 이동을 검사한다.
- **포함 관계:** 파일 → 논리 장면/화면/절 → 대사·선택지·메시지 등 단위를 연결한다. 물리 파일 하나가 여러 장면을 담거나 장면 하나가 여러 파일에 걸칠 수 있다.
- **흐름 그래프:** 확인된 분기 조건, 점프, 호출, 복귀, 선후 관계, 반복 실행을 추적한다. 파일명 알파벳 순서와 이야기 시간순을 동일시하지 않는다.
- **상태:** 화자·수신자·서술자, 관계·호칭 전환, 플레이어 선택, UI 상태, 변수, 사건 이전/이후, 접근 가능한 정보의 차이를 기록한다.
- **불확실성:** 원문에서 순서·조건이 입증되지 않으면 관계를 임의로 확정하지 않는다. 추정 연결은 명시하고 필요한 파일/테스트를 적는다.

흐름 구조가 복잡하다면 조사를 위한 보조 표·그래프·임시 파서를 작성할 수 있지만, 생성한 도구의 결과를 **원문 재확인 없이 사실로 승격하지 않는다.** Skill 자체에 특정 언어·엔진용 실행 코드가 있어야 한다는 전제를 두지 않는다.

## 4. 파일·장면·문맥을 실제로 읽는 절차

각 번역 대상 파일 또는 논리 단위를 다음 순서로 처리한다.

1. 파일의 역할과 전체 구성(텍스트 위치, 이벤트/절 구조, 조건, 참조 대상)을 확인한다.
2. 처음부터 끝까지 접근 가능한 번역 대상 본문을 **실제로 읽고**, 대사/상태/선택/설명 흐름을 따라간다. 단순 패턴 검색이나 선두 일부 샘플만 읽고 완료로 처리하지 않는다.
3. 번역 선택에 영향을 주는 부분은 앞뒤 장면, 해당 주체의 다른 출현, 코드·화면·스토리 상태까지 문맥을 확장한다.
4. 인물·관계·시점·용어·세계관·기능·문체·기술 제약에 해당하는 **주장 가능한 정보**를 추출한다. 관찰, 맥락 확인, 해석, 목표어 제안을 별도 항목으로 둔다.
5. 추출한 각 사실을 원본 ID/위치와 연결하고, 필요한 상세 문서에 기록한다. 단일 문장이 여러 자산을 바꾼다면 서로 참조하되 내용을 중복 확정하지 않는다.
6. 새 규칙이 기존 기록과 충돌하면 적용 범위를 비교하고 반례·예외·이슈를 기록한다. 단순 다수결로 선택하지 않는다.
7. 해당 파일의 `reading_state`와 처리 범위를 갱신한다. 실제 확인한 파일·섹션까지만 `CONTEXT_READ` 또는 `INTEGRATED`로 표시한다.

**의미 분석 결과가 없는 소스의 경우:** 번역 대상 정보가 없거나 기존 규칙과 일치해 추가 문서가 불필요하다고 판단했다면, 조사 범위·판단 근거·연결된 기존 정책을 기록한다. 아무 레코드도 작성하지 않은 채 `INTEGRATED`로 표시하지 않는다.

## 5. 대량 자료 배치 처리

전체 자료가 한 번의 컨텍스트에 들어가지 않으면 파일·장면·기능·루트 등 **문맥이 이어지는 단위**로 배치를 나눈다. 임의의 앞부분 몇 행만 읽는 방식으로 대체하지 않는다.

1. 전체 분모를 먼저 산정하고 조사 배치를 편성한다. `batch_id`, 대상 source/unit 범위, 선행 관계, 상태를 `operations/SOURCES.md` 또는 하네스 내부의 별도 조사 원장에 기록한다.
2. 배치 시작 시 기존 해당 하네스의 README, 진행 원장, 관련 상세 문서의 실제 본문을 읽어 중복 작업과 과거 결정을 확인한다.
3. 배치 본문을 순서대로 읽고 의미 정보·적용 조건·근거를 추출한 뒤 **각 관련 하네스 문서까지 실제로 반영**한다.
4. 배치 종료 전 처리 ID, 생성/갱신한 규칙, 미완료 조사, 다음 파일/장면, 위험한 미해결 조건을 체크포인트로 남긴다.
5. 다음 배치에서 기존에 미확정이던 가설을 확인하거나 반박하면 상세 기록을 갱신하고 변경 이력을 남긴다.
6. 모든 배치를 마친 다음 범위별 원본-지식 매핑과 누락을 다시 대조한다.

시간·도구·컨텍스트 제약 때문에 모두 처리하지 못했다면, **가능한 범위까지 실제 내용을 작성**하고 미처리 범위와 정확한 다음 재개 지점을 기록한다. 자동으로 백그라운드 실행을 약속하거나, 부분 처리 결과를 전체 완료로 보고하지 않는다.

## 6. 누락·접근 실패·변경 관리

- `NOT_READ`: 원본이 존재하지만 아직 열람하지 않았다. `UNKNOWN`: 자료를 읽었지만 특정 사실은 확인할 수 없다. 둘을 합치지 않는다.
- `BLOCKED`: 암호화, 깨진 인코딩, 권한, 파서 실패, 파일 누락 등으로 분석하지 못했다. 상태와 오류·필요 조치를 남긴다.
- `OUT_OF_SCOPE`: 조사 대상이 아니라는 결정에 실제 사유가 있다. 번역 가능 원문을 작업량 감소를 위해 임의 제외하지 않는다.
- 기존 원본의 일부만 확보한 경우 접근 가능 범위·누락 자료·추론 한계를 기록한다. 직접 근거 없이 외부 기억으로 원문 사실을 채우지 않는다.
- 원본이 바뀌면 해시/버전/경로를 다시 대조하고 영향받는 장면·용어·인물·정책만 재분석하되, 전체 분모와 변경 누락을 검사한다.

## 7. 원본 조사 수락 기준

- 모든 범위 내 소스가 `SOURCES`에 등록되고 해당 소스의 상태가 설명된다.
- 번역 대상 본문과 분기·화자·상태 메타데이터를 **실제 읽은 범위**가 확인된다.
- 관련 주장과 정책에 원본 위치가 있고, 미해결 내용에는 명확한 후속 조치가 있다.
- 각 파일이 단순 열람에 그치지 않고 번역 지식 자산에 반영됐거나, 반영할 새 정보가 없다는 근거가 기록된다.
- `DISCOVERED/OPENED` 수준의 파일을 근거로 `전체 원문 검토 완료`라고 쓰지 않는다.

세부 지식 추출과 실제 문서 집필은 [semantic-population.md](semantic-population.md), 진행률·최종 판정은 [coverage-and-resumption.md](coverage-and-resumption.md)를 따른다.

# 프로젝트 Rule 연결 — 번역 전에 하네스 본문을 반드시 읽기

이 문서는 번역 에이전트가 하네스를 **실제로 열고 사용하는 작업 습관**을 프로젝트 Rule에 반영하는 방법이다. 하네스를 만드는 에이전트와 번역을 수행하는 에이전트의 책임을 구분하라.

## 목차
1. 적용 경로 선정 및 기존 Rule 보존
2. `AGENTS.md` 관리 블록 청사진
3. Cursor·Claude 등 환경별 반영
4. 실제 진입 경로 연결
5. 로딩 실효성 확인과 실패 처리
6. 변경/충돌 주의

## 1. 무엇을 언제 갱신할 것인가

1. 현재 프로젝트의 사용 중인 에이전트·편집기와 이미 존재하는 Rule 파일을 읽는다. 프로젝트에 적용되지 않는 모든 플랫폼의 Rule을 기계적으로 생성하지 않는다.
2. 프로젝트 Rule이 없고 사용 환경을 알 수 없으면 프로젝트 루트 `AGENTS.md`를 기본 대상으로 만든다.
3. 이미 Rule이 있다면 **내용 전체를 보존한 채**, 번역 하네스 관리 블록만 삽입하거나 갱신한다. 다른 지침을 삭제하거나 최상위 정책을 임의 덮어쓰지 않는다.
4. 프로젝트에서 실제 사용하는 번역 하네스 경로를 기준으로 연결한다. 기본은 `translation-harness/`이며 기존 운영 위치나 사용자 지정 경로가 있다면 그 위치를 따른다. Rule에는 실제 진입점과 중앙 가이드 경로를 기록한다.
5. 번역·현지화·교정·용어 변경·맥락 검수·번역 QA가 시작될 때 적용하되, 하네스의 최초 구축·내용 갱신·복구 작업 자체에는 파일 부재를 이유로 한 중단을 적용하지 않는다.

## 2. `AGENTS.md`에 넣을 완성형 규칙 블록

기존 Rule의 다른 내용은 보존하고 아래 관리 블록만 삽입·갱신한다. 경로나 파일명이 다르면 현재 실제 문서 위치를 사용한다.

```md
<!-- translation-harness:begin -->
## Translation Harness — required preflight

이 프로젝트에서 번역, 현지화, 번역 교정, 용어 결정, 번역 QA를 시작하기 전에는
다음 절차를 **실제 파일 본문을 읽어** 수행한다.

1. `translation-harness/README.md`를 열어 현재 범위·버전·진입점을 확인한다.
2. `translation-harness/TRANSLATION_GUIDE.md`를 열어 현재 작업 유형에 해당하는
   공통 정책, 분야별 인덱스, 필요한 상세 문서 경로를 찾는다.
3. 현재 번역 단위에 적용되는 `guides/`의 실제 정책 본문과
   `glossary/`, `characters/`, `story/`, `knowledge/`, `media/`의
   **해당 상세 파일·상세 절**을 직접 읽는다. 인덱스/파일명만 보고
   세부 규칙을 읽었다고 간주하지 않는다.
4. 원본 장면/화면/단위의 직접 근거를 확인하고, 승인된 표기와 번역 후보,
   원문 사실과 추측, 텍스트 승인과 실제 실행 검증을 구분한다.
5. 참조할 수 없는 필수 문서나 해결되지 않은 화자·시점·분기·기술 쟁점이
   결과를 바꾼다면 번역을 확정하지 않고 미확정 사항과 필요한 자료를 알린다.
6. 실제 읽은 문서 경로와 적용한 상세 규칙/용어 ID를 작업 기록에 남긴다.

주의: 상위 문서만 읽고 세부 내용까지 확인했다고 주장하지 않는다.
하네스가 없거나 불완전할 때 이를 구축·수정하는 작업은 계속할 수 있다.
이 규칙은 하네스 구축을 막는 선행조건이 아니라 **번역 실행의 사전 확인 절차**다.
<!-- translation-harness:end -->
```

### Rule에서 반드시 나타내야 하는 의미

- **전역 로드:** README와 중앙 라우터는 매 작업 시작 시 실제 본문을 읽는다(이미 읽은 내용이 현재 버전/작업 컨텍스트에서 유효한지 확인).
- **조건부 로드:** 상세 가이드/바이블/용어/기술은 해당 단위에서 필요한 것만, 정확한 본문/앵커까지 읽는다.
- **실제 원문 재확인:** 캐릭터 카드나 용어집의 설명만으로 원문에 없는 정보를 창작하지 않는다.
- **불가 시 처리:** 자료 접근 실패를 보고하고 필요한 범위의 확정을 보류한다.
- **작업 제외:** 최초 하네스 구축·이관·복구 작업은 문서가 없다는 이유로 막지 않는다.

## 3. 에이전트·에디터별 반영 원칙

### `AGENTS.md`가 사용되는 환경

- 프로젝트 루트 `AGENTS.md`가 실제 적용되는지 확인하고 해당 파일에 **중복 없는 관리 블록**을 둔다.
- 기존 문구와 충돌하면 먼저 범위/우선순위를 파악하고 사용자 승인 없이 다른 정책을 삭제하지 않는다.

### Cursor

실제 프로젝트에서 Cursor Rule을 사용한다면 `.cursor/rules/translation-harness.mdc`를 선택할 수 있다. 아래 메타데이터는 **예시**이므로 현재 Cursor의 지원 방식과 프로젝트 설정을 확인한다.

```md
---
description: Read translation harness before translation, localization, editing, or QA
alwaysApply: true
---

[위 'Translation Harness — required preflight' 관리 블록과 동일한 의미의 지시]
```

`alwaysApply: true`를 넣어도 모든 에이전트와 모든 툴이 실제 파일 열람을 강제하는 것은 아니다. 본문이 주입되는 범위와 프로젝트의 Rule 우선순위를 실제 환경에서 확인한다.

### Claude Code 및 기타 환경

- 프로젝트가 `CLAUDE.md`를 사용한다면 기존 내용에 번역 하네스 로드 섹션을 **중복 없이** 추가한다.
- Windsurf, Copilot 등은 실제 도구가 지원하는 프로젝트 Rule 위치·메타데이터를 확인한 후 그 경로에만 반영한다.
- 여러 에이전트를 병용하는 프로젝트라면 관리 블록의 **내용은 동일한 의미로 유지**하되 형식은 해당 도구에 맞춘다. 무조건 다수의 Rule 파일을 생성하지 않는다.

## 4. 실제 진입 경로 연결

- 기본 진입 문서는 `translation-harness/README.md`, 중앙 라우터는 `translation-harness/TRANSLATION_GUIDE.md`다. Rule에는 프로젝트에서 확인한 실제 파일 경로를 사용한다.
- 이미 `localization/` 등 다른 위치에서 운영 중인 경우 실제 경로를 사용하며, 비어 있던 폴더가 채워졌다고 임의로 새 `translation-harness/`를 추가하지 않는다.
- 기존 폴더의 진입점 이름이 `INDEX.md`거나 라우터 이름이 `WORKFLOW.md`처럼 달라도, 같은 역할을 수행하는 실제 파일을 확인하여 연결한다. 별도 루트를 만드는 근거로 삼지 않는다.
- 프로젝트 외부에서 폴더/문서 골격을 받아 활성 루트에 편입한 경우에는 **프로젝트 내부의 실제 파일**을 가리킨다. 외부 제공 경로를 작업 중 참조 경로로 남겨 두지 않는다.
- 파일 이동, 상대 링크 수정, 문서 누락 보완 후 Rule 경로를 대조하고, **이전 경로와 새 경로를 동시에 활성화하지 않는다.**

## 5. Rule 로드 실효성 확인

### 문서 연결 검증

- Rule에서 인용한 최상위 문서가 실제 존재하고 열리는가?
- 중앙 라우터의 **작업 유형별 링크**가 실제 생성된 파일로 이어지는가?
- 캐릭터/스토리 인덱스에서 대상 상세 문서의 해당 절까지 열 수 있는가?
- Rule이 번역과 구축을 혼동하여 초기 구조 생성 작업을 막지는 않는가?

### 실행 흐름 점검

실제 에이전트에 **가상의 작업 시나리오**를 주고 `어떤 문서를 실제로 읽었는지 / 어떤 인물·스토리·용어 상세 절이 필요한지 / 접근 못 한 경우 어떻게 처리하는지`를 점검한다. 성공 여부는 도구별 Rule 로딩 능력에 의존한다. 테스트하지 않았다면 `Rule 파일 갱신 완료, 실제 자동 로딩 미검증`으로 보고한다.

### 단순하고 중요한 실패 사례

- `README.md`만 읽고 상세 캐릭터 절을 읽지 않은 상태에서 인물 말투를 확정함 → 사전 확인 미완료.
- 새 루트가 추가됐지만 중앙 라우터가 이전 루트만 가리킴 → 인덱스/Rule 재점검 필요.
- 하네스 안의 문서를 보완했지만 Rule이 이동 전 경로나 존재하지 않는 기본 경로를 참조함 → 경로 오류.
- 최초 하네스 생성 시 Rule이 아직 없는 문서 읽기를 요구하며 작업을 무한 중단함 → 구축/번역 조건 분리 오류.

## 6. Rule 갱신 안전 수칙

- 관리 블록 구분자가 있다면 그 범위만 갱신하고 다른 사용자 정책을 삭제하지 않는다.
- 구분자가 없다면 같은 의미의 기존 지시를 검색해 중복 없이 추가한다.
- 파일 포맷·줄바꿈·인코딩을 가능한 한 보존한다.
- 프로젝트 Rule에 추가한 번역 지침은 시스템/조직/보안 정책을 무효화하지 않는다.
- 사용 환경에서 명시한 파일의 자동 로딩이 지원되지 않으면 실제 한계를 설명하고, 대안으로 번역 실행 프롬프트에서 필독 본문을 명시하도록 조정한다.

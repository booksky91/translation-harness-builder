# 번역 하네스 정보 아키텍처 및 폴더 생성 명세

## 목차
1. 설계 목적과 산출물 정의
2. 단일 활성 하네스 루트와 기본 계층 트리
3. 각 레이어의 책임
4. 필수·조건부 문서 생성 조건
5. 부모-자식 문서와 링크 규칙
6. 확장·분할·명명·중복 방지
7. 문서 현황 조사와 보강·기존 내용 보호

## 1. 설계 목적과 산출물 정의

번역 하네스는 **공통 번역 규칙**과 **실제 프로젝트 지식을 원문 단위에 연결한 기록**을 함께 관리한다. 출처가 없어도 작성할 수 있는 **양식·운영 규칙**과 원문 확인 뒤 채울 **사실·결정 기록**을 구분한다.

- **문서 골격:** 폴더·Markdown 파일·목차·표 등 정보를 기록할 구조. 문서가 없거나 필요한 구획이 빠져 있으면 본 명세에 따라 만든다.
- **프로젝트 하네스:** 문서 골격에 실제 출처·인물·제품·정책·번역 결정이 연결된 작업 자료.
- **Rule:** 번역 에이전트가 하네스를 먼저 읽도록 하는 프로젝트 수준의 지시. 하네스 문서 그 자체와 혼동하지 않는다.

## 2. 단일 활성 하네스 위치와 기본 계층 구조

번역 지침의 기준 경로는 `PROJECT_ROOT/translation-harness/`다. 사용자가 다른 경로를 지정했거나 기존 프로젝트에서 별도 위치를 사용한다면 해당 경로를 유지한다. 기존 파일·서식은 보존하고 변경할 내용만 반영한다. 같은 프로젝트에 중복된 기준 폴더를 만들지 않는다.

아래 트리에서 `[필수]`는 필수 문서와 그 내용 규격을, `[조건부]`는 해당 번역 판단에 필요할 때 생성할 문서를 뜻한다. 기존 파일의 내용은 보존하고 부족한 섹션·필드·링크를 보완한다.

```text
PROJECT_ROOT/
├── AGENTS.md                           [대상 에이전트에 따라 선택]
└── translation-harness/
    ├── README.md                       [필수: 전체 진입점/범위/로드 순서]
    ├── TRANSLATION_GUIDE.md            [필수: 작업 상황별 상세 문서 라우터]
    ├── PROMPT_TEMPLATE.md              [필수: 번역 단위 입력·출력 계약]
    │
    ├── guides/                          [공통 정책/절차: HOW]
    │   ├── 01_EXECUTION.md             [필수: 작업 프로세스/우선순위]
    │   ├── 02_DIALOGUE_VOICE.md        [조건부: 화자·관계·대사]
    │   ├── 03_NARRATION_STORY.md       [조건부: 서사·시점·정보 공개]
    │   ├── 04_TARGET_STYLE.md          [필수: 목표 언어·문체·표기]
    │   ├── 05_TERMS_AND_NAMES.md       [필수: 용어/명명 판정 정책]
    │   ├── 06_FORMAT_AND_TECH.md       [조건부: UI/자막/엔진/태그]
    │   ├── 07_QA_APPROVAL.md           [필수: 검수/승인/보류]
    │   └── 08_CASEBOOK.md              [조건부: 실제 근거 있는 사례 누적]
    │
    ├── glossary/                        [실제 프로젝트 고유 표기: WHAT]
    │   └── GLOSSARY.md                 [필수: 표제어/사용 조건/미확정]
    │
    ├── characters/                      [조건부: 대화 화자·관계]
    │   ├── CHARACTER_BIBLE.md          [인물 인덱스/기본 공통 규칙]
    │   └── profiles/
    │       └── <character-id>.md        [확인된 화자 수만큼]
    │
    ├── story/                           [조건부: 서사/분기/스포일러]
    │   ├── STORY_BIBLE.md              [서사·루트 인덱스]
    │   ├── FILE_INDEX.md               [원본 파일→장면/루트 매핑 필요 시]
    │   ├── TIMELINE_AND_REVEALS.md     [시점/정보공개 위험이 있는 경우]
    │   └── arcs/
    │       └── <arc-id>.md              [근거로 구분된 루트/장면군만]
    │
    ├── knowledge/                       [조건부: 도메인·제품·세계관]
    │   ├── DOMAIN_BIBLE.md             [도메인 개념/참조 위치 인덱스]
    │   └── topics/
    │       └── <topic-id>.md            [전문 개념/기능별 상세]
    │
    ├── media/                           [조건부: 매체별 구현 요구]
    │   ├── UI_CONTEXT.md               [UI 화면/상태/문구 맥락]
    │   └── SUBTITLE_CONSTRAINTS.md     [자막 타임코드·분할 제약]
    │
    └── operations/                      [필수: 증거·결정·장기 관리]
        ├── SOURCES.md                  [원본/버전/열람 범위/근거 ID]
        ├── DECISIONS.md                [번역 정책·표기 승인 기록]
        ├── ISSUES.md                   [충돌/미확정/차단 사항]
        ├── QA_LOG.md                   [검수/실행 테스트 기록]
        └── CHANGELOG.md                [자산 변경/영향 범위]
```

필수 기본 체계는 **README, 중앙 라우터, 실행 계약, 실행/문체/용어 정책/QA, 용어집, 운영 기록 5종**이다. `AGENTS.md`는 사용 환경에 맞춰 프로젝트 수준에 둔다. 자막·UI·캐릭터·스토리 등이 없는데 그 폴더에 가상의 내용을 만들지 마라.

## 3. 계층별 책임과 정보 흐름

| 층위 | 대표 문서 | 보관할 것 | 넣지 말 것 | 언제 읽는가 |
|---|---|---|---|---|
| L0 진입 | `README.md` | 목표/범위/현재 상태/루트 문서/접근 방법 | 인물별 상세 말투, 루트 전체 줄거리 | 하네스 진입 시 |
| L1 라우터 | `TRANSLATION_GUIDE.md` | 업무별 필독 문서·순서·중단 규칙·우선순위 | 해당 문서의 전문 복사 | 모든 번역 작업 시작 시 |
| L2 공통 정책 | `guides/*.md` | 실행법/문체/용어·QA/기술 보존 원칙 | 프로젝트별 인물의 수십 개 대사 | 상황별 필요 시 |
| L2 작업 계약 | `PROMPT_TEMPLATE.md` | 원본 필드·작업 맥락·참조·출력 스키마 | 특정 작품 정보 하드코딩 | 번역 호출/작업 묶음 시작 시 |
| L2 분야별 인덱스 | 바이블/용어집/도메인 인덱스 | 엔터티·장면·용어 검색키, 상세 위치, 적용 범위 | 상세 규칙을 중복 확정 | 해당 범주 사용 시 |
| L3 상세 지식 | `profiles/`, `arcs/`, `topics/`, `media/` | 적용 조건·원문 근거·번역 영향·예외·미해결 | 다른 레코드의 불필요한 요약 | 해당 인물·루트·화면일 때 |
| L4 거버넌스 | `operations/*.md` | 원본 버전/결정/승인/이슈/QA/변경 | 실제 관찰하지 않은 확정 사실 | 생성·검토·수정 시 |

번역 에이전트의 기본 읽기 동선: **Rule → L0 README → L1 중앙 가이드 → 필요한 L2 정책/인덱스 → 정확한 L3 상세 절 → 원문 → 번역·QA 기록**. L4는 근거·상태 확인이나 새로운 승인/이슈가 발생했을 때 연동한다.

## 4. 필수·조건부 자산의 생성 판정

### 항상 존재와 내용을 보장할 문서

1. README: 실제 존재하는 문서를 링크로 가리키고, 하네스의 현재 준비 상태를 밝힌다.
2. 중앙 가이드: 매체·작업별 라우팅 행을 만든다. 조건부 문서가 아직 없으면 행을 비활성/생성 대기로 표시한다.
3. 단위 프롬프트: 번역 시 입력·출력 조건을 설명한다. 원문 데이터 형식이 없으면 **필드 역할**만 정의하고 특정 필드명을 사실처럼 가정하지 않는다.
4. 실행·목표문체·용어정책·QA 가이드: 해당 정책의 **판정 기준과 절차**를 채운다. 언어·로캘 미확정이면 결정할 항목과 보류 지침을 기록한다.
5. 용어집: 의미 있는 고유 표제어가 아직 없어도 표제어 선정 기준과 실제 사용할 열 정의·상태·예외를 채운다.
6. `operations/`: 근거와 승인·변경을 기록할 명세를 모두 작성한다. 실제 사건이 없으면 빈 기록은 정직하게 `없음/미조사`로 둔다.

### 실제로 관련될 때 존재와 내용을 보장할 문서

- 캐릭터/대사: 화자가 구별되며 말투·호칭·상대가 번역 결과에 영향을 줄 때 `02_DIALOGUE_VOICE`, `CHARACTER_BIBLE`, 확인된 화자 상세 파일을 만든다.
- 시점/서사/분기: 이야기의 시간·서술자·미공개 정보가 번역 선택을 바꿀 때 `03_NARRATION_STORY`, `STORY_BIBLE`, 사건군/루트별 파일을 만든다.
- 기술·매체: 태그, 선택지, 문자열 제한, UI 화면, 자막 타이밍 등 실장 제약이 있으면 `06_FORMAT_AND_TECH` 및 필요한 `media/` 자산을 만든다.
- 전문 지식: 기능·세계관·법률·의학·게임 시스템 등 다중 항목의 정의/맥락이 필요하면 `DOMAIN_BIBLE`, `topics/`를 만든다. 전문적 사실은 확인된 출처만 기록한다.
- 사례집: 실제 실패/모범 사례와 근거가 축적되면 `08_CASEBOOK`을 만든다. 가상 사례를 실제 성공 기록으로 등록하지 않는다.
- 장면·루트별 파일/인물별 파일은 **해당 자료에 근거가 있고 인덱스를 읽는 것만으로 부족할 때** 생성한다. 단순 목록을 불필요하게 파일마다 분리하지 않는다.

## 5. 부모-자식 책임 및 링크 규약

### 상위 인덱스의 최소 구성

- 이 범주가 다루는 정보의 **의미와 범위**.
- `원문 식별자/별칭/파일 패턴/루트/화자/화면` → **실제 상세 문서 링크 및 대상 절 링크** 대응표.
- 어떤 조건에서 해당 상세 문서를 읽을지와 **상세 본문을 열지 않은 경우 판정을 보류**해야 하는 조건.
- 단순 목록과 검증 완료 상태의 구분, 누락/중복 ID 점검, 최신 수정일/상태.
- 상세 문서로 확인하지 못한 내용을 상위 인덱스에서 확정하지 않는다는 규정.

### 상세 자식 문서의 최소 구성

- 상위 인덱스로 돌아가는 상대 링크.
- 고유 ID, 적용 범위(화자/상대/시점/파일·장면/기능), 원문 식별자, 문서 상태.
- 관찰 사실과 설명/추론/번역 제안을 분리한 단락.
- 구체적 언어 선택과 **사용할 수 없는 반례/금지 조건**.
- 관련 용어·캐릭터·스토리·기술 문서 교차 링크.
- 미검증·이슈 ID·담당자와 갱신할 조건.

### 링크 방식

- Markdown **상대 경로**를 사용한다. 하네스를 이동해도 가능한 한 링크가 유지되게 한다.
- 안정된 식별용 앵커를 쓴다. 예: `<a id="char-c001-to-c002-stage1"></a>`. 제목을 바꿔도 외부 링크가 깨지지 않게 한다.
- 인덱스의 행과 상세 파일의 ID를 한 번 대조한 뒤 링크한다. 상세 문서가 없으면 연결된 것처럼 쓰지 않는다.
- 대상 문서가 다른 단계의 관계나 다른 제품 버전을 설명하면, 링크 옆에 **적용 조건**을 명시한다.

## 6. 분할·명명·변경 규칙

- 공통 정책 하나가 여러 상세 지식을 전부 소유하지 않는다. 반복되는 **판정 방법**은 `guides/`, 프로젝트 고유 **사실**은 바이블·용어집·상세 파일에 둔다.
- 상세 문서가 길어도 실제로 함께 읽어야 하는 단위면 유지한다. 분할 기준은 페이지 수보다 **조회 조건**이다(화자/장면/제품 기능 등).
- 새 인물·루트·토픽은 실제 데이터에 등장할 때만 만들며, 인물·루트 ID를 안정적으로 부여한다(예: `C001`, `ARC-001`). 이 번호는 분류 수가 아니라 식별자다.
- 다른 표기와 동일인을 병합하기 전, 출처와 시점이 확인되었는지 확인한다. 이름이 유사하다는 이유만으로 합치지 않는다.
- 원문 파일 순서와 실제 스토리 시간/실행 순서를 동일시하지 않는다. 관계가 확인되지 않으면 `UNVERIFIED_ORDER`로 둔다.
- 문서를 새로 분리하거나 이동할 때 인덱스·Rule·교차 링크·결정 기록에서 역참조를 갱신한다. 임의로 과거 확정 규칙을 제거하지 않는다.

## 7. 현재 문서 골격 조사 및 보강

현재 폴더에 존재하는 파일과 섹션을 확인하고, 이 명세가 요구하는 정보가 누락된 곳을 보완한다.

1. 프로젝트에서 실제로 사용하는 하네스 경로를 하나 지정한다. 기본 `translation-harness/`에서 시작하며 이미 운영 중인 루트나 명시적 사용자 경로는 존중한다.
2. 디렉터리·문서·섹션·표·인덱스·링크를 직접 읽고 **존재 / 누락 / 내용 미작성 / 실제 내용 있음 / 충돌**로 파악한다.
3. 필수 문서가 빠졌다면 위 트리와 문서별 청사진을 따라 **현재 활성 루트에만 추가**한다. 기존 파일에는 없는 필드만 안전하게 채워 넣는다. 조건부 문서는 해당 프로젝트에 필요할 때만 만든다.
4. 제공된 폴더가 프로젝트 밖에 있으면 이름·구조·상대 링크를 최대한 보존해 활성 루트 안에 편입한다. 겹치는 파일은 자동 덮어쓰기하지 않고 이미 쓰인 내용과 빈 골격을 구분하여 병합한다.
5. 기존 섹션 이름이 조금 달라도 의미·용도가 같으면 동일한 책임으로 대응시킨다. **빠진 필수 정보는 기존 틀에도 채워야 한다.** 기존 사용자 승인이나 출처를 잃게 하는 구조 변경은 단독으로 실행하지 말고 충돌로 기록한다.
6. 최종적으로 진입점 → 중앙 가이드 → 정책/분야 인덱스 → 해당 상세 절 → 출처/승인/QA 기록이 **하나의 활성 루트에서 실제로 연결되는지** 검사한다.
7. 문서별 필수 정보와 연결 상태를 검증한다. 파일을 생성했다는 사실만으로 작성 완료로 판정하지 않는다.

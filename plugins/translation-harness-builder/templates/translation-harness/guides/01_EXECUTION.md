# 01 — Translation Execution

> 문서 역할: 번역 단위 처리 순서, 우선순위, 결과 기록 방식의 공통 규정  
> 적용 범위: 모든 번역 단위  
> 문서 상태: SKELETON  
> 기준 근거: `UNKNOWN` (원본 조사 후 기록)  
> 최종 갱신: 미기록

## A. 작업 단위와 매핑
원문의 식별자·소스 버전·번역 가능 필드·수정 불가 필드를 확인한다. CSV, PO, JSON, 자막 등의 실제 필드는 프로젝트 조사 후 이 절에 매핑한다.

## B. 단위별 진행 순서
1. 원본·ID·종류·보호 요소 확인
2. 맥락과 출처 범위 확인
3. [중앙 가이드](../TRANSLATION_GUIDE.md)에 따라 정책 및 실제 상세 절 조회
4. 의미·화자·시점·조건 분석, 번역 초안 작성
5. 의미/문체/용어/기술 QA 및 미확정 기록
6. 실제 읽은 자료·결정 ID와 검토 상태 기록

## C. 판단 우선순위
| 확인 대상 | 우선 적용할 기준 | 충돌 시 |
|---|---|---|
| 보호 요소 | 원본 구조와 기술 명세 | 변경하지 않고 검토 |
| 의미·맥락 | 실제 원문/장면/화면 | 추가 원문 확인 |
| 확정 명칭 | 승인된 적용 범위 | [이슈](../operations/ISSUES.md) 등록 |
| 문체 | [문체 정책](04_TARGET_STYLE.md) | 개별 맥락 우선, 근거 남김 |

## D. 상태 및 결과 기록
근거 상태(`UNKNOWN`/`OBSERVED`/`CONTEXT_CONFIRMED`/`INFERRED`)와 번역 검토 상태(`DRAFT`/`APPROVED_TEXT`), 실장 상태(`NOT_TESTED`/`RUNTIME_VERIFIED`)는 별개로 기록한다.

## E. 금지 작업
원문에 없는 사실 확정, 이름만으로 동일인 판단, 루트 혼합, 태그·ID 수정, 승인 없는 전역 용어 치환을 금지한다.

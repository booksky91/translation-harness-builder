# Translation Unit — 입력·출력 계약

> 문서 역할: 에이전트가 한 번역 단위를 처리할 때 받아야 할 문맥과 반환해야 할 결과를 규정  
> 적용 범위: 단위 번역/수정/검수  
> 문서 상태: SKELETON  
> 기준 근거: `UNKNOWN` (원본 조사 후 기록)  
> 최종 갱신: 미기록

## 1. 작업 목적과 사전 확인
- 원문 의미·화자·시점·용어·기술 요소를 보존한다.
- 작업 시작 전 [진입점](README.md)과 [중앙 가이드](TRANSLATION_GUIDE.md), 해당 가이드·상세 문서를 실제로 열어 확인한다.
- 실제 프로젝트 소스 형식에 맞춰 아래 **의미 필드**를 매핑한다. 필드명이 같다고 가정하지 않는다.

## 2. 입력 필드
| 의미 필드 | 필수성 | 넣을 내용/확인 절차 |
|---|---|---|
| `unit_id` | 필수 | 원본 식별자, 없다면 출처와 위치 기반 임시 ID |
| `original_text` | 필수 | 변경하지 않은 원문 |
| `source_location` | 권장 | 파일/버전/행/장면/타임코드 등 |
| `unit_type` | 조건부 | 대사, 지문, 버튼, 선택지, 자막 등 |
| `context_before_after` | 필요 시 | 실제 의미 판정에 필요한 전후 맥락 |
| `speaker_addressee` | 대사 시 | 화자·수신자·확신도 및 관계 단계 |
| `route_state` | 서사 시 | 장면·분기·시점·현재 공개 사실 |
| `protected_elements` | 기술 시 | 태그·변수·플레이스홀더·타임코드·링크 등 |

## 3. 처리 순서
원본 식별 → 문맥 확인 → 해당 하네스 본문 조회 → 근거·정책 적용 범위 판단 → 번역 후보 작성 → 의미·문체·기술 검사 → 결과와 미확정 기록.

## 4. 출력 필드
| 필드 | 기록할 내용 |
|---|---|
| `unit_id` | 입력과 같은 단위 ID |
| `target_draft` | 목표 언어 번역 후보 |
| `applied_refs` | 실제로 연 상세 문서·절, 용어 ID, 결정 ID |
| `context_decision` | 화자·시점·분기·매체 제약 판정과 근거 |
| `uncertainties` | 미확정 원인·대안·추가 확인 자료 |
| `review_state` | `DRAFT`, `CONTEXT_REVIEW`, `LANGUAGE_REVIEW` 등 실제 상태 |

## 5. 원본 보호
ID·태그·변수·선택지 연결·시간 정보를 임의 변경하지 않는다. 원문 텍스트와 실제 확정 번역문을 덮어쓰기 전에 별도 검증·승인을 거친다.

## 6. 다건 작업
각 단위의 ID·순서·대상을 유지한다. 화자·관계 단계·루트·화면이 바뀌면 필요한 상세 문서를 다시 읽는다.
